6	## 目标
7	
8	给自己做一个跑在 macOS 终端里的、从零实现的独立 TUI 代码编辑器，只服务 C/C++，内置一键编译运行和基于 DeepSeek API 的 AI 辅助；AI 有「练习模式」（只给思路，不给代码）和「写代码模式」（自动补全）两档，用于 ICPC 训练。
9	
10	## 验收标准
11	
12	- 编译出一个独立可执行文件，在 macOS 终端直接运行，不依赖 vim/neovim/VSCode。
13	- 能打开、编辑、保存 `.c` / `.cpp` / `.h` / `.hpp` 文件；有 C/C++ 语法高亮。
14	- 编辑器内一个快捷键即可调用系统编译器（clang/gcc/g++）编译当前文件，编译错误在编辑器内可见并能跳到对应行号。
15	- 编辑器内能运行编译产物，可从一个输入区/文件喂 stdin，看到 stdout 和退出码。
16	- 有一个可见的模式开关，能在「练习模式」和「写代码模式」之间切换，当前处于哪个模式在界面上一眼可见。
17	- 「写代码模式」：光标处停顿后自动请求 DeepSeek，返回结果以灰色 ghost text 显示在光标后，Tab 接受、Esc 丢弃。
18	- 「练习模式」：同一个 AI 入口不会向缓冲区插入任何代码；只在独立面板输出中文的思路提示（算法方向、复杂度、卡点、下一步该想什么）。此模式下 Tab 不接受任何 AI 内容。
19	- API key 与模型 ID 都从配置文件读取，代码里不出现任何硬编码 key 或写死的模型名；配置文件缺失或 key 为空时，编辑与编译功能照常可用，仅 AI 功能提示未配置而不崩溃。
20	- 网络失败、超时、API 返回错误时编辑器不崩溃、不卡死输入，给出可见错误提示。
21	- 附一份 README，说明如何编译本编辑器、配置文件放哪、字段怎么填、快捷键有哪些。
22	
23	## 边界
24	
25	- 只支持 C 和 C++，不做其他语言。
26	- 只跑 macOS 终端，不做 Windows / Linux 适配，不做 GUI 窗口版、不做网页版。
27	- 不做 neovim / VSCode 插件。
28	- 不做 LSP、不做跨文件索引、不做重构、不做调试器集成、不做 Git 集成。
29	- 不做多文件工程 / CMake / Makefile 构建，只编译当前打开的单个文件。
30	- 不做题库抓取、不对接 Codeforces/洛谷等 OJ、不做自动提交。
31	- 不实现 vim 模式的完整键位体系（除非实现过程中判定它是最省事的输入方案，那也只做基本移动/编辑，不做宏、寄存器、ex 命令）。
32	- 不代买、不代配 API key，不写任何绕过 API 计费或鉴权的东西。
33	- 不做打包分发（brew formula、签名、安装器）。

35	## 未知与假设

38	- 假设 DeepSeek API 保持 OpenAI 兼容格式、支持 SSE 流式返回。若实际不兼容，需要改适配层。
39	- 未问：具体实现语言。假设用 C++ 写（与你的使用场景一致，且 macOS 自带工具链可直接编译）。
40	- 未问：是否允许引入第三方库。假设允许使用 libcurl（macOS 自带）做 HTTP，以及一个轻量 JSON 头文件库；终端渲染假设用系统自带 ncurses，不引入重型 TUI 框架。
41	- 未问：具体快捷键偏好。假设由实现方定一套并写进 README，不做键位自定义。
42	- 未问：编译时的默认参数。假设用 ICPC 常见的 `-O2 -std=c++17 -Wall`，且做成配置项可改。
43	- 未问：「练习模式」的提示语言。假设输出中文。
44	- 未问：AI 请求要带多少上下文。假设默认发送当前文件全文，超长时截取光标附近若干行；具体阈值由实现方定。
45	- 未问：是否需要把题面描述喂给 AI。假设不做专门的题面输入区，思路提示仅基于当前代码内容和你在面板里手输的问题。

47	- 未问：是否要保存历史会话 / 学习路径记录。假设不做持久化，关掉即清空。
